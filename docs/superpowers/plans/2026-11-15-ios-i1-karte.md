# iOS I1: Rust-Kern auf iOS und Offline-Karte – Bauplan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eine iOS-App zeigt die Sommer- und Winterkarte samt Hangneigung offline aus einer
installierten Region. Die Kacheln kommen über eine eigene URL aus dem Rust-Kern, dazu der
eigene Standort als Punkt.

**Architecture:** Die neue Hülle `crates/core-ffi` gibt `core-app` per UniFFI an Swift aus.
Die App in `apps/ios/` (SwiftUI, MapLibre Native) hängt ein `URLProtocol` für das Schema
`outdoor-tiles` in MapLibres Netzwerkzugriff ein und beantwortet jede Kachel über
`core-ffi`. Den Style füllt der Kern (`core_maps::style`), Swift lädt ihn nur.

**Tech Stack:** Rust 2024 (Workspace), UniFFI 0.32, Swift 5 / SwiftUI, MapLibre Native iOS
(Swift Package `maplibre-gl-native-distribution`), xcodegen, XCTest/XCUITest.

**Spec:** `docs/superpowers/specs/2026-11-15-ios-app-offline-planung-design.md`. Lies auch
`docs/superpowers/spikes/2026-11-15-ios-valhalla-spike.md` (Abschnitt „Ergebnis“), dort steht,
wie Signieren und Gerätestart auf dem Mac funktionieren.

**Wo:** Task 1–2 auf dem **Linux-Rechner**, Task 3–8 auf dem **MacBook**, in einer eigenen
Claude-Code-Sitzung mit Klon des Repos. Übergabe nur über Git. Nach Task 2 pushen (nach
einmaliger Rückfrage beim Nutzer), dann auf dem Mac `git pull`.

**Nicht in I1:** Höhenlinien (I2), Routing und valhalla-mobile (I3), Freigabe im Heimnetz (I4).
Bis I2 entfernt der Kern die Höhenlinien aus dem iOS-Style. Die Router-Fabrik von außen
(im Entwurf unter I1) und die Profilfarben im Kern wandern nach I3: In I1 wird noch nicht
geroutet. Dass der Kern den Style füllt (Task 1), steht so nicht im Entwurf. Es folgt aus
dessen Anti-Ziel „keine Logik ein zweites Mal in Swift“.

## Stand nach Task 1–2 (Linux, 2026-11-15) – für die Mac-Sitzung

Task 1 und 2 sind fertig (Branch `feature/ios-i1`). Abweichungen vom Text unten, bitte so
übernehmen:

- **Bindgen nur mit Feature:** Der Bin `uniffi-bindgen` braucht `--features bindgen`, damit
  der normale Build die CLI-Abhängigkeiten nicht mitzieht. Erzeugen der Bindings:
  `cargo run -p core-ffi --features bindgen --bin uniffi-bindgen -- generate --library
  target/<ziel>/release/liboutdoor_core.a --language swift --out-dir apps/ios/Generated`.
  Der Bibliotheksmodus funktioniert mit der statischen `.a` (es gibt keine `.so`/`.dylib`).
  Erzeugt werden `outdoor_core.swift`, `outdoor_coreFFI.h`, `outdoor_coreFFI.modulemap`.
- **Swift-Namen** (von UniFFI erzeugt): `CoreApp(dataDir:listener:)`, `overview()`,
  `installLocalRegion(packageDir:)`, `tile(path:)`, `offlineStyle(styleJson:tilesBase:)`,
  Protokoll `CoreListener` mit `onError(message:)`, Fehler `CoreError.Failed(code:message:)`.
- **Kachel außerhalb:** `0/0/0` deckt die ganze Welt ab und liegt damit *in* jeder Region.
  Für „außerhalb“ eine Kachel auf Zoom 12 bei 0°/0° nehmen (in `testTileOutsideRegionIs204`).
- **`overview()` und `offlineStyle()`** lesen über `App::regions()`. Das fragt den Katalog
  ab, sobald eine Katalogquelle gesetzt ist. In I1 gibt es keine, also kein Netz. I4 braucht
  dafür einen Weg ohne Katalogabfrage.
- Der gefüllte Style enthält `metadata.placeholders` nicht mehr.
- **Ausführung:** Der Nutzer hat „direkt“ gewählt (superpowers:executing-plans, Tasks selbst
  umsetzen). Nach Task 8 prüft ein frischer Gutachter den ganzen Branch
  `feature/ios-i1` gegen `main`, einschließlich Task 1–2.

## Stand nach Task 3–7 (Mac, 2026-11-15) – für die Abnahme und den Gutachter

Task 3–7 sind fertig und im Simulator grün (12 Unit-Tests, 7 UI-Tests). Ansatz A trägt:
MapLibre Native 7.0.0 benutzt die Session-Konfiguration, der Selbsttest sieht Kacheln aus
dem `URLProtocol`. Abweichungen vom Text unten:

- **Konstruktor:** UniFFI erzeugt `CoreApp.open(dataDir:listener:)`, nicht `CoreApp(dataDir:listener:)`.
- **Backup:** Nur `Application Support/outdoor/regions` ist vom Backup ausgenommen, nicht der
  ganze Ordner. Sonst fehlte später die Datenbank mit den Tracks im Backup.
- **`-importFixture`** nimmt den Pfad des Fixture-Ordners, nicht den Namen `mini`. Die
  UI-Tests geben den Pfad aus ihrem Bundle mit (der Simulator teilt das Dateisystem des
  Macs). So liegt keine Testregion in der ausgelieferten App.
- **Import im Hintergrund:** Der Start (Kern öffnen, Import) läuft neben dem Hauptthread,
  solange zeigt die App „Karte wird vorbereitet …“. Ein großes Paket würde sonst den Start
  blockieren.
- **Symbole:** 16 × 16 Punkte (64 Pixel), nicht 32 × 32 Punkte. Das entspricht dem Desktop
  (32 Pixel bei `pixelRatio` 2); mit 32 Punkten waren die Symbole doppelt so groß wie dort.
- **Regler-Test:** XCUITest zieht den Regler nur ungefähr (0,14 statt 0,2). Der Test prüft
  deshalb ±0,1 um 0,2 und dass die Ebene dem Regler auf ±0,02 folgt.
- **Statuszeile:** zusätzlich `base=`, `regions=`, `center=`, `import_ms=`, `rendered_ms=`.
- **Standort:** Die App fragt erst beim Tippen auf „Position zentrieren“ nach dem Recht.
  Mit Recht, aber ohne Position nach 10 s lautet der Hinweis „Position noch nicht verfügbar.“
- **Ambient-Cache aus:** `TileURLProtocol.install` setzt MapLibres Zwischenspeicher auf 0,
  damit nach dem Ersetzen einer Region keine alten Kacheln erscheinen.
- **`cargo test --workspace`** baut auf dem Mac Valhalla (Desktop-App) und scheitert daran.
  `region-builder` läuft nur unter Linux (6 Tests melden `Prerequisites(["platform"])`).
  Auf dem Mac: `cargo test --workspace --exclude outdoor-desktop --exclude region-builder`.
- **Paket direkt in `Import`:** Die App nimmt auch ein Paket, dessen Dateien ohne eigenen
  Unterordner in `Import` liegen (so hatte der Nutzer es abgelegt).
- **Task 8:** Die App läuft auf dem iPhone mit `isarwinkel-achensee`, die Messwerte stehen
  im Messprotokoll. Offen ist die Prüfung von Hand im Flugmodus durch den Nutzer.

## Global Constraints

- Mindestversion iOS **16.4**. Testgerät iPhone 13 Pro Max (iOS 27.2) und Simulator. Signieren mit „Personal Team“.
- **Kein Schritt darf ein Netz brauchen.** Der Online-Stil des Desktops kommt auf iOS nicht vor. Der Test auf dem Gerät läuft im Flugmodus.
- **Keine Fachlogik in Swift:** Style füllen, Regionen zusammenführen und Kacheln suchen macht der Kern. Swift ist Oberfläche, Karte und Ortung.
- Texte auf Deutsch. Code, Bezeichner und Commit-Nachrichten auf Englisch, wie im Repo.
- Workspace-Lints gelten (`unwrap_used`, `expect_used`, `panic` = deny), außer `unsafe_code` in `core-ffi` (siehe Task 2).
- Regionen liegen auf iOS in `Application Support/outdoor/regions`, vom iCloud-Backup ausgenommen. Die Datenbank liegt in `Application Support/outdoor/outdoor.sqlite`, wie `outdoor.sqlite` am Desktop.
- Selbsttests treiben echte Eingaben (Tippen und Ziehen im XCUITest), keine internen Aufrufe. Der Nutzer testet die Bedienung zusätzlich von Hand.
- Nach I1 anhalten und dem Nutzer zeigen. Push nur nach einmaliger Rückfrage.

## Review Focus

1. **Keine Region installiert:** Die App startet, zeigt den Hintergrund und den Hinweis „Noch keine Region installiert“. Kein Absturz, keine Endlosschleife von Kachelanfragen. → Task 1 (`style_without_regions_keeps_only_background`) und Task 5 (`testEmptyStartShowsHint`).
2. **Kachel außerhalb der Region oder unbekannte Ebene:** Das `URLProtocol` antwortet mit 204 bzw. 400 und leerem Inhalt, MapLibre zeichnet weiter. → Task 4 (`testTileOutsideRegionIs204`, `testUnknownLayerIs400`).
3. **Unvollständiger Import:** Eine Datei fehlt oder hat eine falsche Prüfsumme. Der Import meldet den Fehler, die Region wird nicht installiert, die App läuft weiter, und der Ordner bleibt zum Nachbessern liegen. → Task 3 (`testBrokenImportReportsErrorAndKeepsFolder`).
4. **Region ohne Hangneigung** (wie `fixtures/regions/mini`): Der Winterstil lädt ohne Fehler, die Ebene `slope` bleibt leer. → Task 6 (`testWinterWithoutSlopeTiles`).
5. **Standort verweigert:** Die Karte geht weiter, der Knopf „Position zentrieren“ zeigt einen Hinweis statt nichts zu tun. → Task 7 (`testCenterWithoutPermissionShowsHint`).

- Produces (Swift sieht das als `CoreApp`, `CoreListener`, `CoreError` …):
  ```rust
  #[uniffi::export(with_foreign)]
  pub trait CoreListener: Send + Sync { fn on_error(&self, message: String); }

  #[derive(uniffi::Error)] pub enum CoreError { Failed { code: String, message: String } }
  #[derive(uniffi::Record)] pub struct TileData { pub data: Vec<u8>, pub mime: String }
  #[derive(uniffi::Record)] pub struct RegionSummary { pub id: String, pub name: String, pub version: String }
  #[derive(uniffi::Record)] pub struct MapOverview {
      pub regions: Vec<RegionSummary>,           // installed only
      pub bounds: Option<Vec<f64>>,              // west, south, east, north
      pub attribution: Vec<String>,
  }

  #[derive(uniffi::Object)] pub struct CoreApp { /* core_app::App */ }
  #[uniffi::export] impl CoreApp {
      #[uniffi::constructor]
      pub fn open(data_dir: String, listener: Arc<dyn CoreListener>) -> Result<Arc<Self>, CoreError>; // db = data_dir/outdoor.sqlite
      pub fn overview(&self) -> Result<MapOverview, CoreError>;
      pub fn install_local_region(&self, package_dir: String) -> Result<RegionSummary, CoreError>;
      /// `path` like "/basemap/14/8700/5720"; Ok(None) = no region has it.
      pub fn tile(&self, path: String) -> Result<Option<TileData>, CoreError>;
      /// `style_json` = contents of styles/topo-*.json; contours omitted until I2.
      pub fn offline_style(&self, style_json: String, tiles_base: String) -> Result<String, CoreError>;
  }
  ```
  `CoreError::Failed.code` ist `AppError::code()`. Ein ungültiger Pfad in `tile` ergibt `code == "tile_path"`. Ein Adapter setzt `CoreListener` auf `core_app::AppListener` um und ignoriert Position, Aufzeichnung und Quellenstatus (kommen später).
